# Ground movement commands — disk research, 2026-11-11

**The main C3 gap is access to controls already in the sim.** This report records the code before this task's implementation: `hold_at`, `resume`, `give_way`, taxi speed and backtrack exist, while the page's key dispatcher omits their keys; `X` already dispatches `World::cross`, including its ahead-of-line behavior. These are primary code observations [CODE-C3, CODE-WEB, CODE-RADIO]. Implementation and test results belong in `HANDOFF.md`; this report does not assert that planned changes passed.

**The source set supports phrase forms, not a complete account of today's Delhi operations.** ICAO Doc 4444 and an older AAI MATS PDF are readable on disk; the saved October 2026 VIDP AIP is readable HTML. No network was used. Current amendment status, NOTAMs, live unit boundaries and actual instruction frequencies were not verified. The filename claiming AAI MATS fifth edition is HTML rather than a PDF; the previous project's MATS seventh-edition citations were therefore not promoted to primary evidence here [FILES, PREVIOUS].

**Every factual column has an evidence grade.** `P` means **primary**: a document or source file read on disk, with a quotation and locator in `sources.csv`. `S` means **secondary**: the earlier project research, not its uninspected original. `R` means **recalled-unverified**: operational interpretation, recalled wording, frequency estimate or design recommendation without direct primary support. A source identifier applies only to the claim beside it. Protection purposes in the catalogue are R interpretation, unless explicitly marked P. “No verified local difference” means this inspection found none; it does not assert that none exists.

**Ground control is a role boundary, not every runway clearance.** This catalogue includes line-up, backtrack on a runway, vacating and urgent stop because the game combines the surface workflow; assigning them all to the real Delhi ground position would be an R assumption. AAI says pilots normally remain on tower until the runway is vacated [P: AAI-AFTER]. Frequency and control-transfer responsibilities remain outside the game's model [P: CODE-RADIO; R: role interpretation].

## Source and model decisions

**The old research contains a hold-short ambiguity that must not drive this implementation.** Its grammar says a root `HOLD SHORT` “stops the aircraft at its current position” [S: PREVIOUS]. The inspected ICAO distinction is `HOLD POSITION` versus `HOLD SHORT OF (position)` [P: ICAO-HOLD]. This report uses H for stop now and J for an exact future node; neither claims to model every published holding position [R: implementation interpretation].

**The map's node is not automatically an AIP holding point.** `hold_points` filters future off-runway route nodes, excludes the route end and does not consult a database of published intermediate holding positions [P: CODE-C3]. A sim-provided label or numeric node ID is suitable game input [R]; it must not be presented as verified Delhi holding-point nomenclature.

**The automatic give-way release already exists in the inspected sim.** `ground_tick` clears the stop after `given_way` says the target has passed, left or rerouted away; `c3_verbs.rs::give_way_waits_until_the_other_has_passed_the_junction` contains a control-conflict comparison and an exact release-tick assertion [P: CODE-TEST]. This is source inspection, not a test-run claim. The game keeps one target callsign and one junction, not a continuous follow clearance [P: CODE-C3].

**The catalogue is broad but cannot claim every possible controller instruction.** It covers the inspected ICAO surface tables, their older Indian equivalents, the user's named families and adjacent safety/parking tasks. Local ad-hoc phraseology, current NOTAM restrictions, military/maintenance traffic, de-icing details, stop-bar control phraseology and live Delhi frequency allocation were not established from this disk inspection [R: limits].
